# Reproducibility

This document specifies the exact environment, commands, and expected
artifacts for reproducing every number in `results/` and every figure
in `plots/`.

## 1. Environment

The reference results were produced on:

- **OS:** Ubuntu 24.04 LTS (x86_64), but any POSIX OS with Python 3.10+
  should work.
- **Python:** CPython 3.12 (also tested on 3.10, 3.11, 3.13).
- **Hardware:** ordinary developer laptop (no special hardware). The
  workloads at default config fit comfortably in 256 MB of RAM.
- **Wall-clock for default config:** ~10 s for the full benchmark
  suite, including plot generation. Tests run in ~0.2 s.

Exact dependency versions are pinned in `requirements.txt`.

## 2. Install

From a clean checkout:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 3. Run the tests

```bash
pytest -q
```

Expected output ends with `45 passed`.

## 4. Reproduce the benchmark CSVs and plots

```bash
python -m simulation.run_all
```

This regenerates:

```
results/benchmark_single_update.csv
results/benchmark_batch_update.csv
results/benchmark_batch_verify.csv
plots/fig_single_update.png
plots/fig_proof_size.png
plots/fig_storage.png
plots/fig_single_verify.png
plots/fig_batch_update.png
plots/fig_batch_verify.png
```

## 5. Determinism

The workload generator is seeded; the benchmark sweeps five seeds
(`--base-seed 42 ... 46`) for confidence-interval estimation. Running
`run_all` twice on the same machine produces byte-identical CSVs.

The verify-time columns are wall-clock measurements and will therefore
vary slightly across machines; the hash-operation counters are
deterministic functions of the workload and will not.

## 6. Larger experiments

To reproduce paper-quality scaling experiments (this will take minutes
to hours depending on machine):

```bash
python -m simulation.benchmark \
  --accounts 10000 100000 1000000 \
  --partition-size 1000 \
  --epochs 50 \
  --lambda-updates 500 \
  --seeds 10 \
  --batch-verify-size 500 \
  --output-dir results

python -m simulation.plot_generator \
  --results-dir results \
  --output-dir plots
```

## 7. What gets logged where

| Artifact | Generated by | Reproducible from |
|----------|--------------|-------------------|
| `results/benchmark_single_update.csv` | `simulation.benchmark` (Scenario 1) | workload generator + smt.py + hd_sms.py |
| `results/benchmark_batch_update.csv`  | `simulation.benchmark` (Scenario 2) | workload generator + hd_sms.py batch API |
| `results/benchmark_batch_verify.csv`  | `simulation.benchmark` (Scenario 3) | hd_sms.py batch prove/verify |
| `plots/fig_*.png` | `simulation.plot_generator` | benchmark CSVs only — no hardcoded values |

No experimental numbers live anywhere in the source code. If a CSV is
missing, `plot_generator` raises `FileNotFoundError` rather than
falling back to defaults.

## 8. Sanity-check commands

To confirm the implementation is actually invoking SHA-256 and not an
estimator:

```bash
python -c "
from simulation.smt import SparseMerkleTree
from simulation.crypto import i128
t = SparseMerkleTree(8)
print('empty root:', t.root.hex())
t.update(7, i128(123))
print('after update:', t.root.hex())
proof = t.prove(7)
print('proof verifies:', SparseMerkleTree.verify(t.root, proof))
"
```

The root hashes should be 64 hex characters (32 bytes of SHA-256) and
should change between updates.

## 9. Comparison with previous prototype

An earlier version of this repository contained only analytical
formulas (`update_cost = log_b(n)`, `proof_size_estimate = depth * 32`)
and a `plot_generator.py` that hardcoded the manuscript's published
numbers. That code has been replaced. Every artifact in this
repository is now generated by an honest run of the supplied code.

If a reviewer encounters any mismatch between a value in the
manuscript and a value in `results/`, the value in `results/` is
authoritative. The manuscript must be updated to match.
